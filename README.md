# Terminal Portfolio

Amar Pratap Singh | github.com/amarpratapsingh | KIIT, Bhubaneswar

## 1. Project Overview

A browser-based terminal portfolio that simulates a real Linux shell. Visitors interact with fake commands such as `ls`, `cat`, `whoami`, and `./contact.sh` to explore work, skills, and contact info. The goal is to create a memorable first impression for recruiters, hiring managers, senior engineers, and the open-source community.

| Concept | Fake interactive shell in the browser - real terminal UX, zero backend |
| --- | --- |
| Audience | Recruiters, hiring managers, senior engineers, open-source community |
| Goal | Memorable first impression that signals Linux depth and frontend craft |
| Deploy | GitHub Pages for the site, Cloudflare Worker for the `curl` endpoint |
| Domain | `amarpratap.dev` or `amarpratapsingh.dev` via Cloudflare Registrar |
| Build time | 1-2 weekends for MVP, 1 more for polish |

## 4. Command System

The command system uses a simple registry pattern. Each command is a standalone module that exports a handler function. The parser splits input by whitespace and looks up the first token in the registry.

### 4.1 Core Commands

| Command | Behavior |
| --- | --- |
| `whoami` | Name, role, university, open-to-work status |
| `ls [path]` | Lists directory contents of the virtual filesystem |
| `cat <file>` | Displays file contents with optional syntax highlighting |
| `cd <dir>` | Changes fake directory and updates the prompt path |
| `pwd` | Prints the current working directory in the fake filesystem |
| `clear` | Clears the terminal and re-shows the prompt |
| `help` | Lists all available commands with short descriptions |
| `history` | Shows previous commands and supports up/down arrows |

### 4.2 Portfolio Commands

| Command | Behavior |
| --- | --- |
| `projects` | Prints project cards with name, stack, and GitHub link |
| `skills` | Colorized skill tree grouped by category |
| `neofetch` | OS-style info card with skills presented as hardware specs |
| `resume` | Prints a plain text resume or prompts for download |
| `open github` | Opens github.com/amarpratapsingh in a new tab |
| `open linkedin` | Opens the LinkedIn profile |
| `contact` | Shows email and socials, optionally opens mailto |

### 4.3 Easter Eggs

| Command | Behavior |
| --- | --- |
| `sudo hire-me` | Prints `Password: ****` and then permission granted |
| `man amar` | Fake man page with SYNOPSIS, OPTIONS, BUGS, and SEE ALSO |
| `rm -rf /` | Fake deletion animation, then a safe joke response |
| `git log` | Fake commit history with a playful portfolio commit |
| `ping recruiter` | Animated ping with a recruiter target |
| `hack` | Matrix rain fills the terminal, then access denied |
| `curl amarpratap.dev` | Tells visitors to run it in a real terminal |

## 6. Virtual Filesystem

The filesystem is a plain JavaScript object tree. Each key is a filename, directories are nested objects, and files are strings. The `cd` and `ls` commands traverse this object to simulate real navigation.

```js
// src/filesystem/fs.js
export const FS = {
  'about.txt': 'CS @ KIIT. Building AI tools and Linux automation...',
  'skills.json': JSON.stringify({ languages: [...], tools: [...] }),
  'resume.pdf': '[binary] - use: open resume',
  projects: {
    'elderly-care-system.md': '# Elderly Care System\n...',
    'automate-suite.md': '# AutomateSuite\n...',
    'ml-experiments.md': '# ML Experiments\n...',
  },
  contact: {
    'github.txt': 'https://github.com/amarpratapsingh',
    'linkedin.txt': 'https://linkedin.com/in/amarpratapsingh',
    'email.txt': 'amar@kiit.ac.in',
  }
};
```

## 7. curl Endpoint (Cloudflare Worker)

The worker detects the User-Agent header. If it is curl, it returns an ANSI-colored text resume. If it is a browser, it redirects to the main site.

```js
// worker/curl-resume.js
export default {
  async fetch(request) {
    const ua = request.headers.get('User-Agent') || '';
    if (!ua.startsWith('curl')) {
      return Response.redirect('https://amarpratap.dev', 302);
    }

    const resume = `
\x1b[1;32m  AMAR PRATAP SINGH\x1b[0m
\x1b[90m  CS Engineer  |  KIIT, Bhubaneswar\x1b[0m

\x1b[1;37m  SKILLS\x1b[0m
  Python - Linux - ML/AI - Docker - Azure - Git

\x1b[1;37m  PROJECTS\x1b[0m
  elderly-care-system  github.com/amarpratapsingh/ECS
  automate-suite       github.com/amarpratapsingh/automate

\x1b[1;37m  CONTACT\x1b[0m
  amar@kiit.ac.in  |  github.com/amarpratapsingh
    `;

    return new Response(resume, {
      headers: { 'Content-Type': 'text/plain; charset=utf-8' }
    });
  }
};
```

## 8. Deployment Pipeline

### 8.1 GitHub Actions - Auto Deploy

```yaml
# .github/workflows/deploy.yml
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

### 8.2 Deployment Checklist

1. Register `amarpratap.dev` on Cloudflare Registrar.
2. Enable GitHub Pages in repo settings, with `gh-pages` as the source.
3. Add the custom domain in Pages settings and set a CNAME in Cloudflare DNS.
4. Deploy the Cloudflare Worker with `npx wrangler deploy`.
5. Add a route in Cloudflare dashboard: `amarpratap.dev/* -> Worker`.
6. Enable Cloudflare Web Analytics in the dashboard.
7. Test with `curl amarpratap.dev` and verify the ANSI resume appears.
